# Public contribution candidate

Use this workflow only when the user explicitly asks to package feedback about Intent Debugger for public contribution.

## Outcome

Produce a candidate that a person without repository write access can review and submit through a public Issue or a Fork-based Pull Request. The candidate is pending maintainer review; it is not an accepted project decision.

## Candidate format

Include:

1. **Problem scenario** — the observed behavior and a concrete example;
2. **Change objective** — what should improve;
3. **Proposed change** — the rule, wording, example, adapter, or evaluation adjustment being suggested;
4. **Preserved boundaries** — what must remain unchanged and what is out of scope;
5. **Possible impact** — affected files, platforms, behaviors, or users;
6. **Open questions** — decisions still requiring maintainer judgment;
7. **Acceptance check** — an observable scenario that would show the change works without breaking existing boundaries.

Distinguish user-provided evidence, reasonable inference, and unresolved items. Keep the wording suitable for copying into the repository's “改进候选” Issue form.

## Permissions and submission

- Generating the candidate does not authorize editing or submitting to the public repository.
- If the user only asks for a candidate, stop after producing it.
- If the user separately asks for repository changes or submission, follow the available tool permissions and external-action confirmation rules.
- A user without direct write access can submit the candidate as a public Issue or make changes in a Fork and open a Pull Request.
- Never describe direct shared write access for all users as the contribution model.
